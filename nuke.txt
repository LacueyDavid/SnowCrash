SnowCrash - How snowcrash_nuke.sh works
======================================

Goal
----
This script connects from level00 to level14, runs /bin/getflag with gdb,
extracts the token from output, then uses that token as the password for the
next level.

In short:
1) login with current token
2) force getflag checks in gdb
3) parse returned token
4) continue to next level


Prerequisites
-------------
- VM running and reachable on localhost:4242
- sshpass installed on host machine
- gdb available inside the SnowCrash VM
- level00 password = level00 (first login only)

Run:
  bash /home/seth/work/snowcrash/snowcrash_nuke.sh


Script walkthrough (line by line logic)
--------------------------------------
1) Variables
   HOST="localhost"
   PORT="4242"
   CURRENT_PASS="level00"

   - HOST/PORT: SSH destination for the VM.
   - CURRENT_PASS: current level password (starts at level00).

2) Main loop
   for i in {0..14}

   - Iterates over levels 00 to 14.

3) Build user + target uid
   LEVEL_USER=$(printf "level%02d" $i)
   TARGET_UID=$((3000 + i))

   - level00, level01, ..., level14
   - target uid follows SnowCrash mapping:
     level00 -> 3000, level01 -> 3001, etc.

4) Status display
   echo -n "[$LEVEL_USER] -> "

   - Prints same line prefix before token result.

5) Remote command through sshpass + ssh
   RAW_OUTPUT=$(sshpass -p "$CURRENT_PASS" ssh ... "gdb ...")

   - sshpass injects password non-interactively.
   - ssh opens remote shell as current level user.
   - command output is captured in RAW_OUTPUT.

6) Why gdb is used
   /bin/getflag has checks that normally block direct token access
   (anti-debug / uid-based behavior).

   The script starts gdb and issues commands with -ex.


About "-ex" (this is gdb, not cat)
-----------------------------------
You asked about "cat -ex".
Important: here it is "gdb -ex", not "cat -ex".

- gdb -ex '<cmd>' means: execute one gdb command at startup.
- You can chain many -ex options to automate an entire debugger session.

Used in script:
- -ex 'set pagination off'
  Disable "--Type <ret> for more--" pages.

- -ex 'set confirm off'
  Disable interactive confirmations.

- -ex 'break *0x804898e'
  Breakpoint right after ptrace call/check.

- -ex run
  Start program execution.

- -ex 'set $eax = 0'
  Force return/register state so anti-debug path is bypassed.

- -ex 'break *0x8048b06'
  Breakpoint around uid-based branch logic.

- -ex continue
  Continue until next breakpoint.

- -ex 'set $eax = $TARGET_UID'
  Pretend uid is target one in register.

- -ex 'set *(int*)($esp+0x18) = $TARGET_UID'
  Also patch stack value used by comparisons.

- -ex continue
  Resume and let getflag print token.

- -ex quit
  Exit gdb.


How token parsing works
-----------------------
NEW_TOKEN=$(echo "$RAW_OUTPUT" \
  | grep -i "Check flag" \
  | sed -E 's/.*token[[:space:]]*:[[:space:]]*([^[:space:]]+).*/\1/' \
  | tail -n1 \
  | tr -d '\r')

Step by step:
- grep -i "Check flag"
  Keep lines containing token message (case-insensitive).

- sed -E '...'
  Extract only the token after "token :".

- tail -n1
  Keep last match if multiple lines appear.

- tr -d '\r'
  Remove CR character from mixed line endings.


Error handling
--------------
if [ -z "$NEW_TOKEN" ]; then
  echo "ERROR: Could not extract token."
  break
fi

- If parsing fails, script stops immediately.
- Otherwise, CURRENT_PASS becomes NEW_TOKEN and loop continues.


Why this works level after level
--------------------------------
Each token is the next account password.
So after level00 token is found, it is used to connect as level01,
then level02, and so on until level14.


Common issues and fixes
-----------------------
1) "Permission denied" on script
   Run with bash explicitly:
   bash /home/seth/work/snowcrash/snowcrash_nuke.sh

2) VM not reachable
   Check that QEMU is running and port 4242 is forwarded.

3) Token parsing fails
   Add debug print:
   echo "$RAW_OUTPUT"
   Then inspect exact line around "Check flag".

4) Wrong current path in shell
   Use absolute paths when launching script.


Quick summary
-------------
- This is an automated debugger pipeline.
- gdb -ex runs a scripted sequence non-interactively.
- Script patches runtime checks, extracts token, chains credentials.
- It repeats until all levels are processed.
